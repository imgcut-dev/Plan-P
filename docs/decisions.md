# 의사결정 기록

정한 것을 날짜와 이유와 함께 적는다. 새 결정은 위에 추가한다.

## 2026-11-17 (8) 정렬 조정은 측정으로 한다

- **글씨 세로 가운데를 눈이 아니라 숫자로 잰다.** 처음에는 모든 알약·버튼 아래 여백을 0.12em 늘렸으나, 측정해 보니 한글 라벨은 이미 가운데(±0.5px)였고 오히려 0.8px 위로 치우쳤다. 어긋난 것은 영문 라벨(Home 등)뿐이라 그것만 보정했다.
- **헤더 내비는 `flex:1 1 0`.** 메뉴가 많아도 도구(검색·관리자)가 아래 줄로 밀리지 않는다. 규칙은 `DESIGN.md`의 "정렬 규칙".

## 2026-11-17 (7) 추천과 댓글

- **Firestore에 직접 구현한다.** giscus는 독자가 GitHub 계정이 있어야 하고 디자인이 어긋나며, Disqus는 광고·추적이 붙어 "광고 없음" 원칙과 맞지 않아 쓰지 않았다.
- **작성자는 Google 로그인만 쓴다.** 스팸이 적고 추천 중복 방지가 확실하다. 이름과 프로필 사진만 저장하고 이메일은 저장하지 않는다. 로그인 없이 읽을 수 있다.
- **댓글은 바로 공개하고, 문제가 있으면 관리자가 숨기거나 삭제한다.** 승인제는 관리 부담이 크다. 숨긴 댓글은 규칙이 막아서 사이트에서 읽을 수 없다.
- **구조:** `posts/{글}/comments/{댓글}`(`uid,name,photo,text,createdAt,parentId,status`), `posts/{글}/likes/{id}`. 추천 문서 id가 글 추천은 `uid`, 댓글 추천은 `댓글id_uid`라서 한 사람이 한 번만 누른다(다시 누르면 취소). 추천 수는 문서 개수를 센다.
- **대댓글은 1단계까지.** 규칙이 부모 댓글에 부모가 없을 때만 허용한다. 길이는 500자.
- **규칙이 방어한다:** 쓰기는 로그인한 본인 `uid`로만, 삭제는 본인 또는 관리자, 숨기기는 관리자만. 연속 작성 간격(10초)은 화면에서만 막는다(규칙으로 막으려면 별도 문서가 필요해서 보류).
- **알려진 한계:** 댓글을 지우면 그 답글은 목록에서 보이지 않게 된다(관리자 "댓글 관리"에서 따로 지운다). 글을 지워도 댓글 문서는 남는다. 신고 버튼과 글 목록의 댓글 수 표시는 만들지 않았다.
- **배포 순서:** `firestore.rules`를 먼저 배포한 뒤 호스팅을 배포한다.

## 2026-11-17 (6) 방문 통계(Google Analytics 4)

- **GA4를 쓴다.** 홈 방문자, 페이지(글)별 방문자, 지역·기기·OS, 인기 글을 보려는 것이다. 측정 ID는 `analytics.js`의 `GA_ID`(공개 값이라 커밋해도 된다). GA 계정은 "Plan-P Blog Platform", 속성 "Plan-P Blog Platform", 스트림 `plan-p`.
- **구글이 주는 GTM 코드를 붙이지 않고 `gtag.js`를 직접 쓴다.** 이 사이트는 주소의 `#/`로 화면을 바꿔서 GA가 글 단위를 구분하지 못한다. 그래서 `send_page_view:false`로 자동 전송을 끄고, 화면이 바뀔 때마다 `#/post/글ID`를 `/post/글ID`로 바꿔 직접 보낸다(`gaView`).
- **GA 설정에서 "향상된 측정 > 페이지 조회 > 브라우저 기록 이벤트 기반 페이지 변경"을 꺼야 한다.** 켜 두면 GA가 `#` 이동도 자동으로 보내서 조회수가 두 배로 잡힌다.
- **집계에서 제외:** 로컬(`localhost`), 관리자 화면(`analytics.js`를 불러오지 않음), 미리보기(`?demo`, `?skin`). 검색은 입력이 멈춘 뒤 한 번만 보낸다.
- **푸터에 안내 문구를 넣는다.** "이 사이트는 방문 통계를 위해 Google Analytics를 사용합니다." 통계를 켠 환경에서만 보인다. 방문자를 한국에서 받는 사이트라서 알리는 것이 안전하다.

- **이벤트는 `docs/analytics-events.md`의 규칙표대로 만든다.** 처음 5개: `search`, `read_progress`, `tag_click`, `category_click`, `select_content`. 이름은 `대상_동작` 소문자 밑줄, GA 권장 이름이 있으면 그것을 쓴다. 조회수만으로는 "끝까지 읽었는지"를 알 수 없어서 `read_progress`를 넣었다.
- **이벤트는 두 종류로 나눈다.** 코드 이벤트(클릭, 읽은 비율, 검색어 같은 행동)와 GA "이벤트 만들기"로 만드는 이벤트(`page_view` 주소 조건으로 화면 종류를 잡는 `view_post`, `view_category`, `view_tag`, `view_search`). 후자는 코드 배포 없이 만들 수 있지만 클릭이나 읽은 비율은 못 잡는다. 이름은 `view_대상`, `대상_click`, `대상_progress`로 종류가 보이게 짓는다(택소노미는 `docs/analytics-events.md`).
- **GA 맞춤 측정기준 5개(`post_id`, `percent`, `tag_name`, `category`, `source`)는 GA에서 직접 등록한다.** 등록 전 데이터는 소급되지 않으므로 코드 배포 전에 만든다.

## 2026-11-17 (5) 글 관리 목록

- **글 관리 목록에 검색, 필터, 정렬, 페이지 나누기, 전체 선택과 일괄 처리를 둔다.** 검색은 제목·요약·카테고리·태그를 찾고, 필터는 상태·카테고리·태그, 정렬은 최신순·오래된순·제목순, 페이지는 10·20·50개씩이다.
- **전체 선택은 현재 페이지 기준**이고, 페이지가 모두 선택되면 "검색 결과 N개 모두 선택"이 나온다. 필터나 검색을 바꾸면 선택을 풀어서 보이지 않는 글을 실수로 처리하지 않게 한다.
- **일괄 처리는 발행, 비공개, 삭제.** 삭제는 확인창을 거친다. 발행한 글에 새 카테고리가 있으면 카테고리 목록에 자동 추가한다(글 하나를 발행할 때와 같은 규칙).

## 2026-11-17 (4) 태그

- **글에 태그(`tags`, 문자열 배열)를 둔다.** 카테고리(글이 속한 분류, 메뉴와 연결)와 따로, 글을 찾을 때 쓰는 짧은 단어다. 글 하나에 10개, 태그 하나는 20자까지.
- **관리자 입력은 Enter 또는 쉼표로 추가, ✕로 삭제.** 이미 쓴 태그는 자동 추천에 나온다. `#`을 붙여 입력해도 지운다.
- **사이트 표시.** 글 상세 아래에 `#태그` 링크(`#/tag/이름`, 그 태그의 글 목록)를 보여 준다. 카드 아래 해시태그는 태그가 있으면 태그, 없으면 예전처럼 카테고리를 보여 준다. 검색은 태그도 찾는다.
- **태그는 메뉴와 연결하지 않는다.** 메뉴는 카테고리만 쓴다.

## 2026-11-17 (3) 스킨 추가

- **스킨 `reader`, `studio`를 추가했다.** WordPress 테마 Ury와 PortfolioWP 데모의 분위기(왼쪽 사이드바·세리프 / 굵은 제목·파스텔·노란 형광펜)를 참고해 직접 만들었다. 코드와 이미지는 가져오지 않았고, 이름도 따로 지었다.
- **WordPress 테마 목록 페이지(wordpress.com 테마 전체, 블로그 필터)는 스킨 하나의 시안이 될 수 없다.** 100개가 넘는 서로 다른 테마의 목록이라서, 쓰고 싶은 테마 이름이나 캡처를 정해서 받아야 한다.
- **사이드바 같은 배치 변화는 CSS만으로 한다.** `reader`는 900px 이상에서 헤더를 왼쪽 고정 사이드바로 바꾸고, 좁은 화면에서는 위쪽 헤더로 돌아간다. HTML은 바꾸지 않는다.
- **스킨 미리보기 주소.** `?skin=이름`은 그 스킨과 기본 포인트색으로, `?demo=1`은 샘플 글로 사이트를 보여 준다(저장하지 않고 확인하기 위한 것). 관리자 디자인 탭의 미리보기와 "새 창으로 열기"가 이 주소를 쓴다.
- **스킨을 고르면 포인트색이 그 스킨의 기본값으로 채워지고**, "이 스킨의 기본 색으로 되돌리기" 버튼이 있다.

## 2026-11-17 (2) 관리자와 메인 화면

- **관리자에서는 "카테고리" 한 단어로 통일한다.** 글쓰기에서는 카테고리, 관리 화면에서는 메뉴라고 불러 헷갈린다는 의견이 있었다. 상단 메뉴 대부분이 카테고리라서 탭 이름도 "카테고리 관리"다. 홈, 전체 글 링크의 순서도 같은 화면에서 정한다.
- **카테고리는 이름만 입력하면 만들어진다.** 같은 이름의 글 목록(`#/cat/이름`)으로 자동 연결한다. 주소를 사람이 고르게 하지 않는다(처음 보는 사람이 이해하기 어려웠다). 홈이나 외부 주소로 바꾸는 것은 "바꾸기"에서만 한다.
- **글을 발행할 때 새 카테고리가 목록에 없으면 자동으로 추가한다.** 임시저장은 추가하지 않는다(비어 있는 카테고리가 먼저 보이는 것을 막으려는 것이다).
- **글이 있는 카테고리를 삭제하면 글 처리를 먼저 묻는다.** 다른 카테고리로 옮기거나 카테고리만 뺀다. 글은 지우지 않는다. "글 옮기기"로 카테고리를 합칠 수도 있다. 이 변경은 Firestore에 바로 저장한다.
- **글에 이미지가 없거나 주소가 깨지면 기본 이미지(`placeholder.svg`)를 보여 준다.**
- **메인 화면은 섹션을 쌓은 목록(`home.sections`)이다.** 웹빌더 프로젝트의 "모듈 스택" 구조를 가져왔다. 섹션 종류: 카테고리 버튼, 추천 글, 대표 글(+소개), 최신 글, 카테고리별 글, 텍스트·배너. 새 종류는 `data.js`의 `SECTIONS`와 `index.html`의 `SEC`에 추가한다. `sections`가 없는 예전 설정은 예전 구성(추천 3 → 대표 → 최신)으로 해석한다(`homeSections`).
- **글은 관리자 화면에서 목록 팝업으로 골라 꽂는다.** 직접 입력하지 않는다. 임시저장 글은 고를 수 없다.
- **스킨(디자인 틀)을 고를 수 있다.** 스킨은 색, 글꼴, 모서리만 바꾸고 HTML 구조와 콘텐츠는 그대로다. 사이트가 스킨 id 하나(`site.skin`)를 저장한다. 스킨을 고르면 그 스킨의 포인트 색이 `site.accent`에 채워지고, 이후 포인트 색은 따로 바꿀 수 있다. 첫 스킨은 `plan-p`, `journal`, `dark` 세 개이고, 더 예쁜 스킨은 사용자가 보내는 화면 캡처를 바탕으로 추가한다. 규칙은 `DESIGN.md`가 기준이다.
- **웹빌더 프로젝트의 코드는 가져오지 않고 구조만 참고한다.** 그쪽은 Next.js와 SQLite 기반이라 이 정적 사이트와 맞지 않는다. 모듈 스택과 디자인 팩 개념만 작게 구현했다.
- **글 이미지 업로드는 아직 없다.** Firebase Storage를 켜야 하고(요금제 확인 필요), 켜기 전까지는 이미지 URL로 넣는다.

## 2026-11-17 (1) 로그인과 데이터

- **관리자 로그인은 Google 로그인만 쓴다.** 비밀번호를 우리가 다루지 않아도 되고 관리자가 한 명이라 충분하다. Firebase의 이메일/비밀번호 로그인은 꺼 두었다(켜 두면 누구나 가입 요청을 보낼 수 있다).
- **관리자 여부는 Firestore 규칙이 판단한다.** 규칙은 로그인한 이메일이 관리자 이메일이고 인증된 계정일 때만 쓰기를 허용한다. 화면(JS)에서 막는 것은 보조이고, 진짜 방어는 규칙이다.
- **관리자 이메일은 저장소에 올리지 않는다.** 이메일이 들어 있는 `firestore.rules`는 `.gitignore`에 두고 이 PC에서만 `firebase deploy --only firestore:rules`로 배포한다. 규칙 내용(정책)은 이 문서가 기준이다.
- **글 접근 정책.** 발행된 글(`status: published`)과 사이트 설정은 누구나 읽는다. 임시저장 글은 관리자만 읽는다. 화면에서 숨기는 것이 아니라 DB가 막는다.
- **데이터 구조.** `site/config`(사이트 설정·메뉴·메인) 한 문서와 `posts/{id}` 글 문서. 글을 따로 둔 이유는 글마다 공개 여부를 규칙으로 가르기 위해서다.
- **DB를 못 읽으면 샘플 데이터(`data.js`의 DEFAULT)를 보여 준다.** 처음 배포나 장애 때 빈 화면이 되지 않게 하려는 것이다.
- **에디터는 TOAST UI Editor(MIT), 본문은 마크다운으로 저장한다.** 이미지는 URL로만 넣는다. 업로드가 필요해지면 Firebase Storage를 연결한다.
- **디자인은 파랑 하나, 그림자 없음.** 값은 `design-system/tokens.json`, 규칙은 `design-system/README.md`가 기준이다.
